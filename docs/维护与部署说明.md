# 维护与部署说明（Windows 单机）

本文面向 Windows 单机部署（主电脑即本机），覆盖初始化、日常维护、故障排查和插件说明。
多台电脑协作的局域网模式见《工作室局域网使用说明》。

## 1. 首次初始化（Windows）

```powershell
# Python 3.11+、Node 20+ 必须可用
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 前端工作台（本仓库使用 npm 的 package-lock.json；如本机只有 pnpm，可用 pnpm 安装）
cd collector/workbench-command-center
npm install          # 或 pnpm install
npm run build        # 或 pnpm run build   -> 输出到 dist/
cd ../..

# 本地配置
Copy-Item ozon-adapter\shops.example.json ozon-adapter\shops.json
Copy-Item .env.example ozon-adapter\.env.default
# 在 ozon-adapter\.env.default 填写自己的 Ozon Client-Id / Api-Key
```

启动工作台：

```powershell
# 方式一：命令行
.\.venv\Scripts\python.exe -m uvicorn app:app --app-dir collector/local-ingest --host 127.0.0.1 --port 8765

# 方式二：仓库脚本（推荐，自动检测端口、后台运行、打开浏览器）
.\scripts\start-workbench.bat
.\scripts\stop-workbench.ps1
```

访问 <http://127.0.0.1:8765/workbench>。

## 2. 浏览器插件（1688 采集）

1. Edge 打开 `edge://extensions`，Chrome 打开 `chrome://extensions`。
2. 开启“开发人员模式”→“加载已解压的扩展”→ 选择 `collector/edge-extension`。
3. 插件默认连接 `http://127.0.0.1:8765`；如改了工作台地址，在插件弹窗的“主电脑连接”里填写并“保存并连接”。
4. 修改插件代码后必须点“重新加载”才会生效。
5. 1688 商品详情页右下角有“JLC 采集”悬浮按钮：检测页面 → 采集 → 右侧选 SKU 与类目。
6. 已打开的 1688 页面若读取失败：按 F5 刷新页面即可（插件会自动注入内容脚本）。

## 3. 日常维护

- **改前端后**：`cd collector/workbench-command-center && pnpm run build`（或 npm run build），并递增 `collector/local-ingest/app.py` 里的 `COMMAND_CENTER_VERSION`，然后重启工作台。
- **日志**：`logs/workbench-service.out.log`（运行日志）、`logs/workbench-uvicorn.*.log`、`logs/device-activity.jsonl`、`logs/ozon-category-refresh.log`。
- **重启**：桌面快捷方式“JLC 工作台-停止”→“JLC 工作台”，或上述脚本。
- **备份**：`products/`（商品数据）、`ozon-adapter/metadata/`（类目缓存）、`ozon-adapter/.env.default` 与 `ozon-adapter/shops.json`（凭据/店铺）。建议定期打包。
- **依赖升级**：先跑 `tests/` 与手工回归再升级；`requirements.txt` 为锁定版本。

## 4. 故障排查

### 工作台一直超时/卡死
- 历史根因：`/api/workbench/market-intelligence/search-visibility/sync` 在事件循环里同步调用 Ozon，Ozon 网络慢时会卡死整个服务。已修复（`asyncio.to_thread` + 10s 超时）。
- 仍超时：查看 `logs/workbench-service.out.log` 最后 20 行；用“停止→启动”恢复。

### 插件无法连接工作台
- 确认工作台在运行：浏览器打开 <http://127.0.0.1:8765/health>。
- 插件弹窗“测试连接”应显示“已连接共享工作台”。
- 历史根因：插件默认地址曾写死为局域网 IP `192.168.3.13` 并把 `127.0.0.1` 当旧地址强制替换；已修复为默认 `127.0.0.1:8765`，并对旧错误地址自动重置。

### 插件“无法读取页面”
- 确保当前标签页是 `https://detail.1688.com/offer/数字.html` 商品详情页。
- 在 1688 页面按 F5 刷新后再打开插件。
- 插件 v0.4.28+ 会自动注入内容脚本，旧页面无需手动刷新。

## 5. 已知问题（Windows 兼容）

- `collector/local-ingest/collector_routes.py` 的 `_pid_is_alive()` 使用 Linux 的 `/bin/ps`，Windows 上恒返回 True（不影响主流程，批处理恢复判断暂时失效）。
- `collector/local-ingest/collector_routes.py` 的“打开文件夹”用 macOS 的 `/usr/bin/open`，Windows 上会失败。
- README 主要面向 macOS，Windows 步骤以本文为准。
